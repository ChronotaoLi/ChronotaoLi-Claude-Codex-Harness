# Personal Harness contributor notes

Read `README.md` for usage and `docs/design.md` for constraints and reference sources.
Runtime code is in `harness/`, common agent instructions in `shared/`, and offline behavior tests in `tests/`.
`operator/harness-operator/SKILL.md` is the skill for the outer session that calls Harness; it stays out of `shared/skills/`, which the roles see.
Configuration is two files: the operator file (`--config`, default the root `harness.toml`) and the target repository's `.harness/project.toml`, which alone holds verification commands and worker grants. Tests that need those set them explicitly (for example `write_project_config` in `tests/test_harness.py`) rather than relying on the root `harness.toml`. The reference suite and shards isolate developer Git configuration through `tests/git_isolation.py`, imported by `test_harness` and `tests/run_shards.py`. It uses private `HOME` and `XDG_CONFIG_HOME` directories, `GIT_CONFIG_GLOBAL` pointing to an empty file, and `GIT_CONFIG_NOSYSTEM=1` for the test process and its children. A standalone test module gets this isolation when it imports one of those entry points. Use `fixture_git` for fixture Git commands.

Keep the core Python 3.11+ and dependency-free. Run `python3 -m unittest discover -s tests -v` after runtime changes; `python3 tests/run_shards.py` (default `--shards 4`) runs the same discovered tests in parallel processes and exits non-zero unless every collected test ran exactly once. The single-process command remains the reference run.
Tests must exercise lifecycle behavior, acceptance gates, isolation, retrieval or recovery rather than matching prompt wording.
The stop tripwire enforces by default. An uncovered unclassified finding fails the owning test. It observes CLI stops, operation records, run ledgers and exceptions escaping watched entry points in the test process. A separately launched Harness CLI child is outside that coverage. One finding may group several publications, each of which needs coverage. The tripwire recognizes injected fixture failures. Otherwise use a specific nonempty `allow_unclassified` reason scoped to an intentional fixture publication, or `consume` when the test checks the publications explicitly. Classify production stops at the boundary that knows their cause.

A whole-test skip stays skipped and can still produce findings in the report. A skipped subtest leaves its owning test subject to enforcement. Set `HARNESS_STOP_TRIPWIRE_REPORT` to save optional JSONL evidence, including exempt findings. A report write failure leaves the test result intact and can leave a `.incomplete` marker and a `stop tripwire: report incomplete:` diagnostic.

Preserve exact model IDs configured by the user. Workers and reviewers must get fresh processes and dispatch IDs; never add implicit resume, model fallback, recursive agents, or automatic merges.
A configured quota wait (`runtime.quota_wait_max_seconds`) is a bounded wait inside the same process after a classified subscription-limit failure; it re-runs every scheduling gate, is not a resume, and never restarts a process that has died.
On waking it first re-runs `resume`'s read-only precondition checks (the same `RunLifecycle` functions), never `resume`'s preflight steps that write, and it does not reload the configuration.
Do not claim a simulated test proves a model call works. `python3 -m harness smoke` invokes real accounts and is a separate integration check.
Keep private run state under `.harness/`; avoid committing transcripts, credentials or generated MCP configuration.
Keep external-project field-test reports and in-progress test logs under ignored `.harness/`, not in versioned project documentation. `docs/validation.md` records completed Harness verification results, not test progress or external task status.
