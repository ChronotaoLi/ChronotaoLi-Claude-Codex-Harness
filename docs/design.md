# 设计取舍与参考

本项目把模型当作可替换的决策与执行部件，把任务状态、权限边界、证据和接受条件留在确定性的运行时。指挥保有逻辑上的连续性；它的历史由检查点提供。执行者与审阅者是一次性的。

## 状态与接受条件

通常为 `planning → running → completed`，最后还必须通过整体目标验收。可选计划确认进入 `awaiting_approval`，分步执行在任务边界进入 `paused`；异常进入 `blocked` 或 `interrupted`。这些是本地运行状态，与任何外部产品的自动化目标状态无关。所有 worker 和 reviewer dispatch 始终使用新进程，指挥也通过台账恢复上下文。

操作者可显式将未完成运行标为 `abandoned`，此后不能 resume；分支与证据保留。可选移除 worktree 必须在运行锁内确认旧进程退出、路径归属与 HEAD，拒绝未保存文件（含忽略文件）及隐藏索引标记，并独立核对已跟踪内容。删除意图先持久化，删除完成但记账中断时通过路径缺失及 Git 注销状态恢复。resume 获锁后重新读取台账，防止覆盖并发放弃操作。

一个任务只有在以下条件同时满足时才进入 accepted：

1. 当前 dispatch 返回匹配 ID 的合法结果，声明完成且无 blocker。
2. Git 工作树的管理目录、公共目录、链接文件和分支绑定未变，HEAD 未被 agent 改动，文件变更落在任务的 allowed_paths。
3. 所有配置验证命令成功，且没有修改待审阅文件。
4. 新 Sol 实例返回 approve，没有未处理的 blocking findings；advisory 可以保留。
5. 接受前文件快照等于审阅时快照。

分支提交、结果记忆和台账都带来源引用。review 失败或测试失败只保留诊断，不提升为长期成功经验。身份不匹配、结构非法、权限错误和范围违例停止运行。语义非法也不能接受；其中身份和结构正确且明确含拒绝或阻断的非格式修正调用的审阅可进入独立的 `invalid_rejected` 恢复路径，有界格式修复与它分开，均不能放宽接受条件。

审阅问题使用稳定 ID、严重级别、类别、位置、说明和证据。偏好只能是 advisory。返工审阅收到历轮问题与对应证据，既要复核旧问题，也要独立检查整个当前修改；运行时不因为 worker 的辩解而豁免门禁。原始目标和任务义务独立保留，全部任务接受并提交后重新执行验证，并由新的 reviewer 审阅原始 base 到当前 HEAD 的完整 diff。任务验证发生在接受提交之前，最终验证覆盖提交后的状态，不能以命令相同为由省略。最终文件快照不变才允许 completed。整体拒绝需要通过正常门禁的修复任务，重复 resume 不能对同一拒绝结果重新抽签。

文件范围从仓库根目录匹配，普通 `*`、`?`、字符集合只作用于单个路径段；独立 `**` 路径段匹配零个或多个层级。因而 `src/*` 不包含 `src/a/b.py`，`**/*.py` 包含根目录的 `main.py`。规划时拒绝不合法范围、显式受保护根路径和不存在的 skill；接受门禁仍独立拒绝受保护路径变更。路径不做裁剪或 Unicode 规范化，以免改变实际文件名。

指令文件可以属于合法编辑范围。任务审阅按当前候选、整体审阅按原始 base 到 HEAD 的完整变更，分别列出根级及嵌套的 `AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md`、`CLAUDE.local.md`，覆盖新增、修改、删除和重命名涉及的路径。诊断标记为 `untrusted_candidate_instructions`，要求独立核对其对后续派发的影响；候选内容不授予改变原目标、接受条件或工具权限的权力。这是明确的审阅输入，不将合法指令维护永久禁止，也不声称阻止原生 CLI 自动读取候选规则。

## 调度、再规划与恢复

当且仅当一个任务就绪、没有失败反馈且尚未尝试时，运行时可直接发送包含目标、任务、依赖结果、验收和可用命令的完整简报。选择或返工仍交给指挥。指挥是否复用会话与是否支持再规划是两个独立问题，本设计保留每次重新组装上下文。

指挥选择就绪任务时，以目标和所有就绪任务的标题检索记忆，避免只使用列表首项的任务信息。

再规划只处理任务拆分、缺少前置工作和整体验收发现的工程缺口。worker 通过 `blocker_kind` 区分 task 与 environment；CLI 错误、权限、范围违例和现场不一致不会被包装成自动再规划。非法结果默认停止；明确归属且保留拒绝证据的 invalid_rejected 整体审阅可自动进入修正规划，操作者请求的有界非法结果修正另述。指挥返回 `{action, reason, new_tasks, updates}`：每个 update 仅包含 `id`、`description`、`add_depends_on`，stop 必须提供空操作数组。运行时在原计划上应用增量并重新检查 DAG，要求：

- 保留每个既有任务 ID，已接受任务完全不变。
- 未接受任务只可更新描述并添加依赖；标题、skills、验收和 allowed_paths 均从台账保留，已有依赖不得删除。
- 新任务只使用已有 allowed_paths 中的模式，或操作者显式加入 approved_scope 的模式；不通过推测 glob 包含关系放大范围。
- 原始任务继续承担最终集成义务，拆分不能删除或重命名它来避开失败。
- 每次修订保存版本与原因。校验通过后先持久化待应用修订，再归档未接受修改并恢复隔离工作树，保留已接受提交。归档阶段中断时，恢复继续应用同一修订，不重复调用指挥或增加再规划次数；新的归档尝试保留独立目录。

`resume --allow-scope PATTERN` 可重复指定，仅用于 pending/request 阶段的再规划或已停止的再规划。先校验整批模式，再追加审计事件并保存去重后的 `approved_scope`；非法或显式受保护根路径使整批失败。授权只扩大新任务可选模式，不修改原始任务、既有任务的范围与验收，也不改变预算。已返回的越界修订可在新授权下校验同一 receipt，原结果仍保留；已校验修订不可追加范围。停止状态不因授权解除，必须另用 `--retry-stopped` 才重新请求规划。

每任务尝试数、整个 run 的 worker 尝试数、有效再规划数、最终验收次数和模型派发数均持久保存且受上限约束。分别由 `max_attempts`、`max_total_attempts`、`max_replans`、`max_final_attempts`、`max_agent_dispatches` 控制。再规划修订通过完整校验后才计数；合法 stop 及下述仅原因文本格式错误的 stop 同样计数，请求故障和未知 skill 不计入有效再规划数。所有实际模型调用（含失败、格式修正）消耗独立的派发额度，默认 200 次。最终验收默认 3 次，独立于任务预算。新任务与 resume 都不清零累计预算；额度耗尽保留待再规划意图，操作者增加预算后继续修正规划。

待再规划意图在任务、run、最终和再规划预算守卫之前持久化。保留原有预算上限：最后一次任务尝试返回 task blocker 时，先停在该上限；操作者增加对应预算后直接恢复指挥再规划，不先重派 worker。结构合法、空操作且明确 stop 的结果若仅原因文本格式错误，也计入次数并持久停止，保留原文、格式诊断和返回产物，不能由普通恢复重新抽取决定。

worker 尝试与派发计数在本地上下文、hooks、快照和额度预检成功后，调用后端之前同一次保存。准备失败不扣额度，调用后端失败计数；派发前失败也将对应条目标为 failed 并确认没有遗留进程。格式修正共用此入口。

经校验的指挥 stop 持久保存原触发条件、原因和证据；普通 resume 不重新派发。显式 `--retry-stopped <task_id|final>` 重新打开该规划请求，不先重跑已受阻 worker，不清零任何预算。整体拒绝后若接受了未改变快照的修正任务，记录已处理的修正任务集合并保存新的 pending_replan；再次请求规划受原预算约束，原整体拒绝始终保留，不重新审阅同一快照。

整体验证以非零退出失败后的空 diff 修正采用相同处理：保留失败记录，直接请求新的修正规划，不额外消耗最终尝试来重跑相同代码。显式 `--reverify` 仍可用于操作者确认环境已修复的情况。

恢复配置允许增加上下文预算、agent/验证超时、Claude 轮数和上述次数上限。操作者也可以追加精确 `worker_commands` argv，已有授权不可删除或修改；事件记录旧值、新值和新增命令。模型 ID、供应商、effort、验证命令和共享资产不允许在同一 run 中改变。进程存活和 Git HEAD 检查仍在恢复前执行；无法探测进程组权限时按仍存活处理。台账版本 8 增加 `invalid_repairs` 和 `approved_scope`；版本 7 及更早运行不能直接恢复，不自动迁移，也不补造旧运行的修正额度或授权。版本 7 已有的 Git 绑定和验证证据仍可用于独立清理命令。当前版本已完成的 run 在普通 resume 时直接返回保存结果，不再核对用于继续执行的配置和共享资源。

对长时间中断后 pgid 被复用的情况，采用显式确认而非根据组长身份自动推断整个进程组已退出。`resume` 与 `abandon` 的 `--confirm-exited <dispatch_id>` 在运行锁内校验全部 ID，先追加操作事件，再只更新指定记录的退出确认。事件记录当时的组存活探测及组长 PID、PPID、PGID、启动时间和命令名（或探测错误）；组长缺失不构成自动退出证明，不发送终止信号。确认不放宽其他恢复或工作树移除检查。

worker 完成且结果通过检查后，持久化 `pending_task` 的 verifying 阶段及完整快照摘要；验证成功后持久化 reviewing 阶段、diff、验证产物路径、记忆提案和历轮审阅。恢复时先检查范围、HEAD 和快照；一致则继续未完成阶段，不再派发 worker 或消耗 worker 额度。验证重跑使用新的日志目录。候选变化使后续证据失效，回到新的工作尝试；越界残留先停止并提示人工核对清理，不自动删文件，不派发模型或消耗 worker 额度。

候选变化时，先将已返回的审阅及格式修正原始依据保存到历史，保留 dispatch、原快照、产物路径、摘要和校验错误，再清除待审阅状态。结构与身份可确认的 findings 传给后续实例复核，其余产物只作为带诊断的原始证据引用。已绑定产物缺失或篡改仍阻止恢复；失效批准不构成新候选的接受依据。

审阅派发在调用模型之前保存 `review_receipts` 接收意图，绑定原 dispatch ID、候选快照和结果文件位置。返回结果原子落盘后即使还没完成检查就中断，恢复也读取该结果，完成原契约身份、结构、语义、格式、文件一致性和 post_agent hook 检查。结果绑定哈希后，文件缺失或改变必须停止；hook 重试使用独立日志并具有至少一次执行语义。没有返回结果的调用可在人工 resume 后重新派发，仍消耗派发预算。协议错误不能通过重抽结果消失。

非格式修正调用的审阅的身份、结构和快照正确，但 finding ID 重复、blocking 缺少证据／属于偏好或记忆批准越界时，若 verdict 为 request_changes 或包含任意 blocking finding，则保留为 `invalid_rejected`。该状态保存完整原文、产物摘要和语义诊断，不修造一份合法结果，也不批准记忆；post_agent hook 仍须通过。任务级保存历史后返工，整体级保存完成的失败记录与 pending_replan，再按原预算请求修正。相同整体快照包括空 diff 修正均不可重抽审阅；不含拒绝的非法批准默认停止，仅下述显式元数据修正可继续。身份／结构错误及格式修正中的非法结果继续停止。无效语义结果可能同时超过格式大小限制；历史通过原始产物引用和有界摘录传递，必要元数据仍超预算时明确停止。

整体验收在 `final_history` 中持久化 verifying/reviewing 阶段及证据。中断且快照相同则复用同一次最终尝试；未完成记录不作为先前审阅结论注入。验证失败使用独立的 verification_failed 状态：所有失败项均超时时停止，人工修复环境或增加超时后 resume 可在同一快照上重验；普通非零退出进入修正规划，同一快照重验须显式 `--reverify`。重验消耗新的最终尝试且保留原失败记录。该选项只可取消尚未返回指挥结果的验证失败再规划请求；已返回结果必须完成原校验，已校验修订必须继续应用，模型拒绝仍要求正常修正任务。最终拒绝结果与待再规划意图一起保存，避免中断丢失修正路径。

普通运行错误记录类型、证据并进入 blocked；角色调用故障单独保存为 `last_runtime_error`，不污染其他角色的任务反馈。用户中断、SIGTERM 和 SIGHUP 进入 interrupted，并清理所拥有的进程组。验证超时记录为 `timed_out`、退出码 124，任务级进入正常返工反馈，最终级按上述恢复策略处理。缺少 CLI、损坏供应商 JSON 等明确阻断，不作通用网络重试，也不切换模型。默认配置属于 Harness 自身，`--repo` 不自动选择项目配置；真实项目应显式指定 `--config`，启动时显示所用配置和验证 argv。

worker 调用失败或中断时，另按 task ID 保存 `worker_recovery`，记录故障类型、dispatch ID、证据目录和变更文件；同任务的调度、后续 worker 与 reviewer 通过 `recovery` 收到其来源。格式失败也可能伴随实际编辑，因此格式修正成功不提前清除这项来源。保留可用的范围内进度，不自动复位；越界残留仍先阻止派发。其他任务没有此项反馈，接受或应用再规划后清除该来源。

配置采用封闭键集合，拒绝未知顶层节和各节、角色字段，错误给出完整键路径。`status`、`memory` 与 `cleanup-verification` 不加载运行配置；源码外安装执行任务需显式提供配置和共享资源。运行事件、预检提示与 demo 横幅写 stderr，结果 JSON 保持 stdout 可独立解析。

计划确认和单步执行为显式选项：默认连续执行；选择暂停确认后必须显式批准。任何无回复或重复恢复都不能代替批准。step 以一个已接受任务为边界；最后一个任务之后还需要整体检查。

指挥 plan、replan 和 dispatch 同样采用派发前 receipt：保存原 schema、输入包及摘要、dispatch、候选摘要、返回位置；结果原子落盘后继续原身份、结构、任务语义和格式校验。replan 另绑定持久请求 ID，合法新修订不能误用前次结果。结果摘要确定后缺失或篡改停止。post_agent 使用独立日志，保留至少一次语义；receipt 与计划、停止或已校验修订在同一次台账保存中消费。模型生成的任务选择先保存为 pending_directive，worker 本地准备失败保留它，调用后端前与尝试预算一起消费。已返回的指挥结果不再由普通恢复重新抽取；未返回结果的故障仍可显式恢复，格式修正保持原有一次额度。

`resume --repair-invalid DISPATCH_ID` 提供独立、显式且有界的语义修正入口。仅匹配当前未消费的 receipt，先验证原字节摘要、派发身份、结构、当前快照，以及指挥请求摘要和 replan 请求归属。适用对象为非法 plan/revise，或 verdict 为 approve、没有 blocking finding，但重复 finding ID／批准未知记忆 key 的审阅。合法结果及其 hook 失败、stop、任务选择、拒绝或 blocking 审阅、身份／结构错误、已有格式修正均不适用；finding 数量、位置、内容或证据等不可变字段超限也不派发无解修正。纯格式错误继续使用原有格式修正协议。

授权与原 receipt 一起持久保存在 `invalid_repairs`，保留原结果文件、内容摘要、快照、诊断和指挥请求。每个角色／调用类型／任务整个 run 只可授权一次；新派发使用新进程、新 dispatch，并消耗累计派发预算。指挥修正仍受原目标、范围、DAG、验收与预算约束。审阅修正必须保留原 verdict、全部 finding 的数量、顺序、严重程度、类别、位置、说明和证据，以及原先获批且确属提案的 key；只允许修改摘要、重复或非法 ID，并去重批准 key、删除不存在的 key。原本合法且唯一的 finding ID 不变，不允许新增批准。

原始依据在准备、派发和接收修正时继续核验。已返回的修正结果由新 receipt 完成同一校验与 hook，不因再次非法、格式错误或中断自动增加派发；未返回结果的 CLI 故障可普通 resume 继续，保留授权并计入预算。完成、失败或待处理的修正记录均不清零，任务候选变化仍走原审阅证据归档路径。`--repair-invalid` 与 `--reverify`、`--retry-stopped`、`--allow-scope` 互斥，不能组合成丢弃结果或扩大权限的捷径。

结构与语义正确但格式超限的 blocked/task worker 结果先保存完整证据和 pending_replan，再停止；resume 直接请求有界再规划。环境 blocker 仍停止，不将权限或服务故障变成工程再规划。恢复中校验 receipt 的错误同步更新 dispatch 及 last_runtime_error，避免仅 run 状态反映故障。

## 项目记忆的提升与过时

任务历史与可复用项目知识分别保存。任务结果使用 run/task 唯一 key，不互相覆盖。接受台账、后续依赖简报和任务记忆使用 reviewer 基于代码与证据独立形成的摘要；worker summary 留在执行证据中，不直接提升为成功知识。worker 可提交有界的知识提案，但没有直接写记忆工具。审阅者逐项核实来源并返回 approved_memory_keys；代码通过不能隐含批准提案。

必要上下文保留原始目标、验收、范围和未解决问题，日志与重复内容通过证据引用缩减。每条验证命令的 stdout/stderr 摘录合计最多 500 字符，保留 argv、退出状态和完整日志路径。审阅历史仅合并完全相同的 finding；变化后的严重程度、说明或证据保留独立记录及全文引用，旧摘要保留产物引用。当前计划与原始计划相同则传入 `tasks_ref: "original_tasks"`；再规划后以 `tasks_base_ref` 和可无损重建的 `tasks_delta` 传入新增任务、描述更新和新增依赖，不重复嵌入未变义务。接受摘要引用各任务独立审阅产物。最终文件快照独立落盘，台账只保存内容摘要和路径；门禁仍重新哈希完整内容，不使用 mtime/size 缓存代替完整性检查。

契约允许的大型审阅保持原始结果与接受语义不变，在输入层压缩文本：审阅历史共享 9,000 字符的序列化额度，反馈和格式修正引用相同的有界表示。每条问题的 ID、severity、category 和所有产物引用必须保留，location/message/evidence 可以摘录，并明确要求行动或判定解决前读取全文。旧审阅在删除重复 finding 或摘要前保存原始内容摘要，裁剪后未超预算也保留；反馈据此去重，同时区分摘录相同而原文不同的审阅。没有全文产物引用时不压缩。标识及引用的必要开销优先于摘录预算，超出全局预算仍停止；这不是任意长度历史都能装入默认上下文的承诺。

worker 反馈使用共享 9,000 字符序列化额度，保留完成／阻断语义、数量、提案 key 和原始结果摘要及路径；文本摘录不改变完整结果或待审阅提案。没有全文引用时不压缩；使用引用前核验文件内容摘要，原文缺失或篡改停止。

初次执行任务和应用再规划前估算整体审阅容量，包含实际规则、契约、计划、已接受结果和先前完成的审阅证据。必要内容下限已超预算时保存计划并停止，允许增加上下文预算后恢复；对尚未接受任务预留每条 600 字符摘要、每条验证命令 500 字符输出及路径长度，预计超限只提前警告。该估计不能保证未来历史、转义字符和实际输出的大小；正式派发始终以真实序列化后的字符数检查预算。

只有已接受任务中的明确获批提案才能写入 `knowledge:` 命名空间。写入校验相对来源路径、文件哈希、批准 key 和操作者所有权；存在操作者历史的 key 不得被自动提案替代。可选记忆的来源或所有权不满足条件时，记录诊断并丢弃该批提案；非法审阅批准 key 属于协议错误，阻止接受。

自动任务历史和项目知识默认有 180 天召回期限，操作者事实默认无期限；均保留历史证据。知识来源改变或提交不可核实时，召回标记 possibly_stale 并降权。类型权重只作为相关性排序的辅助信号，不把人工记录视为永远正确。没有自动模型整理或语义冲突覆盖。

词法记忆检索仍扫描有效记录，并在单次请求内缓存来源核验。暂不引入索引或跨请求缓存，以保留当前过期、来源变化和排序语义；数千条以上记录的检索成本需要单独测量，当前没有大规模记忆库的延迟保证。

同一项目的多个 run 各有工作树和运行锁，共享项目记忆；跨 run 检索到的知识依然需要核验来源。初始化使用数据库真实路径旁的持久 `.init.lock` 文件和等待式文件锁，覆盖 WAL 设置、建表与迁移，不锁整个 run；常规读写仍使用 SQLite 事务锁。只读 memory 子命令不创建数据库、不迁移或修改 Git 排除配置，已有库使用 SQLite mode=ro，允许 SQLite 管理 WAL 辅助文件。

接受提交与台账保存后，任务记忆、批准提案、接受事件及 post_accept 按持久待办依次完成，成功前不能派发后续任务或 completed。任务记忆使用有界摘要与审阅产物引用，不嵌入契约允许的完整大型审阅。SQLite 将稳定操作 ID、请求摘要和结果 ID 与实际记忆写入同事务保存；恢复重复操作返回原结果，不新增版本、刷新 TTL 或覆盖后来版本。接受事件通过稳定 ID 去重，可选知识提案校验失败保存丢弃诊断，存储故障保留待办供重试。恢复补完待办计入 step 的接受边界。Git commit 与接受台账写入之间的中断仍因 HEAD 不符停止，要求人工核对。

## 共享工具与 hooks

生命周期 hooks 是可配置的运行时门禁，默认不附带策略。初始化时完整校验事件对象、脚本列表、argv 和正有限超时值，任何事件的无效配置都会在脚本执行前被拒绝。上下文组装事件命名为 context_prepared，保留旧名 context_compacted 作为互斥别名。暂不增加原生工具 hooks 翻译层：两端事件语义和权限效果需要按实际需求单独验证。

`post_agent` 作用于通过结果校验的调用，以及明确归类为 `invalid_rejected` 的审阅；其他非法结果在它之前停止。至少一次语义描述的是已进入 hook 门禁后的执行与重试，不要求所有非法输出都调用 hook，也不将 hook 成功视为结果合法的替代证明。

pre_accept 前持久化审阅通过的快照摘要、证据和待接受阶段。hook 拒绝、超时或无法启动时保留结构化错误与日志引用；恢复时快照相同则只重试门禁，无需重复派发该任务的 worker/reviewer，且每次尝试保存独立日志。快照变化则丢弃旧批准，重新执行任务、验证及审阅，不能把先前结论用于新文件。post_accept 的待执行状态与接受台账一起保存，失败后恢复先重试该门禁，成功后才清除。这些 hook 具有至少一次执行语义，脚本需能处理重复执行。共享资产摘要使用版本域、逻辑资源身份和带长度边界的内容，支持字节一致的 Harness 安装搬迁；目标仓库和运行状态本身仍使用原路径。摘要不递归追踪任意脚本及其依赖，后者由配置维护者保证一致。

post_accept 在每次执行前持久增加 hook_attempts，写入 `post_accept-N` 独立目录；on_error 同样在停止记账时分配 `error-N`。恢复不会覆盖此前的失败日志。

Git 文件快照还包含暂存区条目摘要；范围检查同时检查暂存变更，提交前从已接受 HEAD 重建暂存区，再仅加入审阅过的路径。仅存在于原暂存区、且已从工作树删除的新文件在重建后跳过；真实的已跟踪删除及符号链接仍提交。再规划归档同时保存工作区与暂存差异，遇到路径祖先是符号链接时停止，避免归档写入跟随链接。验证产生的未忽略文件也属于快照变化，会留下文件差异诊断；应配置或忽略实际生成产物，不普遍豁免新文件。

运行时所有工作树快照与范围检查还直接拒绝工作树内部的 `.harness` 文件、目录和符号链接，避免本地 Git 排除规则隐藏该保留路径；项目根目录的真实运行状态除外。索引含 160000 模式的仓库在创建 worktree 前拒绝，单独存在 `.gitmodules` 文件不作为拒绝依据。验证生成文件可由操作者核对后精确加入公共 Git 目录的 info/exclude，既有已跟踪文件不受豁免。

保留全量内容哈希，不按 mtime、size 或 Git 的未变判断复用文件摘要。仅在相邻调用之间没有 hook、验证命令或模型执行时复用刚获得的快照；验证后的全量比较证明该候选未变，可将同一候选写入证据。单任务一次通过的离线流程由 20 次降至 15 次全量快照，恢复、hooks、审阅后及接受前的完整性检查保留。成本仍随文件数和内容大小增长，当前不承诺对大型仓库的性能上限。

Claude 只读角色获得受限 Git 查询命令，worker 可配置额外的精确 argv 授权，包括必要时带明确路径的删除或移动命令；默认不开放通用 `rm`、`mv`，也不新增命令前缀授权。CLI 仍可能内建只读命令许可，配置中的额外 argv 并非所有可执行命令的穷尽清单。CLI 授权是能力配置，不能替代 OS 隔离。Codex 适配器当前只提供只读模式，配置其为 worker 时提前拒绝；不会替换模型来迁就适配器。

Claude worker 通过 `Edit(//<resolved-worktree>/**)` 将内置 Edit、Write 写入授权限定到工作树，按字面转义路径中的 gitignore 模式字符，不保留裸 Edit／Write 授权或无效的 Write(path) 规则。它不限制任意脚本间接写文件；读取证据的权限和登录环境保持原配置。Codex 调用传入 `--sandbox read-only`。两种调用不具有相同的执行约束，也不承诺对工作树外读取的隔离。shared 配置四个资源路径须提前校验；doctor 按配置实际引用的 CLI 判定可用性。

独立的 `python3 -m harness.permission_smoke` 使用真实 Claude worker 账号与原模型 ID，在 `.harness/permission-smoke/` 的专用 Git 现场检查权限。它保留原始 stream-json、工具调用和结果、最终 permission_denials、文件内容检查及报告；被拒绝的测试必须实际发起匹配的工具调用并得到对应拒绝，模型文字不作证。测试涵盖允许的内置读写、精确 Bash、额外参数与未列命令、工作树外读写和 `.git` 修改；外部读取按现有 Read 授权应成功。专用精确命令替换项目 worker/验证命令，外部 MCP 关闭，故不执行项目命令或访问其外部服务。该命令消耗账号额度，结果仅覆盖现场和 CLI 版本，不证明完整命令许可策略或 OS 隔离；离线证据解析测试不代表真实 CLI 已通过。

完整输出契约保存在 schema.json 并由本地校验。两种供应商使用仅含基础类型、字段、必填、枚举与数组项结构的投影，另存 provider-schema.json；模型输入的 output_constraints 从同一契约生成长度、数量、非空、唯一性及标识符格式限制，本地仍强制执行，不假设两端支持相同 JSON Schema 扩展。

审阅输入另提供 uniqueBy=id、blocking 条件下 evidence 至少一项且类别不能为 preference、approved_memory_keys 的提案子集等机器可读约束。无提案包括 final_review 时批准数组 maxItems=0。预估最终上下文与实际派发使用同一生成函数；这些约束不扩展供应商 wire schema，也不替代本地校验。

校验先检查身份、结构、权限及任务／审阅语义，再检查这些可修复格式限制。仅格式错误允许每个角色／调用类型／任务组合在整个 run 内自动修复一次，额度不随 resume、新尝试或新快照清零。格式修正单独保存，不混入任务反馈，成功或候选失效时清除待修正状态。当前计划格式边界由规划检查作为硬错误拒绝。修复启动新进程、新 dispatch，传入错误和上次证据引用，必须重新检查当前文件；worker 修复同时消耗任务及整个 run 的尝试预算。缺字段、错类型、无效枚举、身份不匹配、越权、语义矛盾或 CLI 故障均不走该路径。

worker 的修正派发身份在调用后端前与预算共同保存；返回结果一经落盘即结束 pending 修正，恢复也检查该返回位置以覆盖落盘与清理之间的中断。指挥修正结果由 receipt 继续处理原校验和 hook，硬错误或已耗尽的修正不重新抽取。再次失败后，worker 的人工 resume 是携带最近故障来源的新普通尝试，不重放旧修正；尝试和派发额度继续累计。准备失败或 CLI 没有返回结果时保留修正状态。

worker 已报告 blocker 时，即使同时存在格式错误也保留阻断并停止，不自动重派。reviewer 格式修复必须保持原 verdict、获批知识 key 集合以及所有 finding 的数量、顺序、严重程度、说明和证据；只允许改写摘要、修正非法 finding ID 和去重批准 key。该约束与快照一起持久化，恢复不能通过重抽审阅消除原有阻断问题。修正调用的 CLI/超时故障保留原守卫，人工恢复可以重派修正；实际改变原结论或 findings 将守卫标为 failed。检测到任何不可变字段格式超限时先标记 unrepairable，不派发无解的修正；修正已返回但再次格式失败或额度已用时标记 exhausted。后两者也禁止对同一快照重复派发。其他身份、结构或语义错误同样阻止接受；非法拒绝按 invalid_rejected 保留证据并返工，少量非法批准元数据可经上述显式授权修正，其余已返回的非法结果持续保留并校验，不能借普通恢复改抽。

修正守卫也绑定原始结果内容摘要，读取时验证，缺失或篡改直接停止。结构非法并不等于没有审阅结论：多余字段也可能伴随明确拒绝，因此不提供通用 discard-review 出口。操作者可放弃运行并保留证据，不能用恢复参数抹掉已有阻断。

Git 绑定在 worktree 创建后按实际解析结果捕获，不猜测 Git 管理目录名称。保存 .git、gitdir 反向链接、commondir 摘要及实际目录、预期分支；每个工作树 Git 命令显式传入 git-dir/work-tree，并排除环境中的 Git 重定向。操作前后核验绑定，symbolic-ref 解析还拒绝 run 分支间接指向主分支。接受、归档、恢复、移除和记忆来源核验均使用绑定。detached 验证工作树额外固定提交；分支运行只允许运行时接受后推进检查点。文件快照单独按索引模式拒绝 gitlink，同名文件替换为目录按原文件删除及子路径变化处理。上述措施收紧运行时自身的提交目标，不构成对并发恶意进程的 OS 隔离。

可选 verification.fresh_checkout 在仓库之外的私有临时目录创建全新 detached worktree，只用于整体验证；verification.setup_commands 是操作者声明的精确 argv，不授予 worker 能力。准备阶段只能生成忽略产物，不能改变受检代码；失败停在当前最终尝试，恢复使用另一新检出并保留旧日志。验证同时核对新检出和原 run 候选，审阅只在验证完成后派发。新检出路径、绑定、准备和验证证据保留，当前不自动清理。默认保持原工作树验证方式；设置在 run 内不可变化。该模式减少忽略文件残留与父目录依赖影响，但仍受当前环境、Git 配置及显式准备命令影响，不承诺 hermetic 构建。任务工作树仍位于项目内部，向上查找的工具可能读取主检出依赖。

`cleanup-verification RUN` 独立于运行配置，支持版本 7、8 台账，默认在运行锁内预览已记录的全新验证检出。`--remove` 先确认派发进程退出、外部路径归属、Git 绑定和固定验证提交，并独立核对内容及索引；已跟踪修改、未跟踪和忽略文件、隐藏索引标记均拒绝清理。各检出单独返回结果，符合条件者可移除，受阻者保留。原台账、checkout.json、日志和 diff 不改写，新增绑定原证据摘要的 cleanup.json，删除意图先落盘，以恢复移除与记账之间的中断。目录已缺失而 Git 注册仍在时，只能核验原反向链接、公共目录及 detached HEAD 后注销该精确路径，不使用全仓库 prune，也不触及其他运行。

初始、worker 返回和验证结束记录折叠的忽略路径清单、增减及全文摘要引用，审阅者收到诊断。清单不是内容哈希，对已有忽略文件及目录内部变化无完整性保证。内置 MCP 使用 mode=ro 记忆连接，不进行初始化或迁移；不存在数据库时返回空检索。

## 为什么先串行

多模型分工不要求同时写代码。串行 DAG 能先验证模型路由、一次性实例、门禁和恢复协议；每个 run 独立工作树保证原始工作区不受普通任务编辑影响。后续并行需要进一步实现每任务工作树、依赖提交集成和冲突处理，不能只加线程池。

## 仍需明确的限制

这不是恶意代码隔离系统。原生 CLI、配置的 hooks、验证命令和 MCP 服务在用户权限下运行；只读声明、prompt 和 Git 范围检查不是完整的 OS 权限边界。强隔离应使用专用 OS 用户或容器，并在那个边界内运行本编排器。

SQLite 是长期记忆的存储真相；JSON 导出和 Markdown handoff 提供可检查产物。没有自动学习新技能、语义冲突检测、向量数据库、夜间 consolidation 或精确 token 计费。这些都可独立增加，不改变 task/dispatch/acceptance 契约。
