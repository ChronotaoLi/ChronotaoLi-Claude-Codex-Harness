### 变异、中断注入与离线探针

“变异”指在任务的工作树里把关键判定改错、确认有用例失败，再恢复；变异不进版本库。

- 各实施任务都对新用例做了变异检查，例如返工提示 5 种、页面分区 6 处、页面里按数据值查表 17 处、命令的加载用例 58 处。
- 审阅容量：一批的登记是一次台账转换，对 `SIGINT` 是原子的；一个审阅 dispatch 只登记一次。13 次连续拒绝之后，在默认上下文预算下仍能走到批准；这只在一组 finding 长度下测过，同样密度下第 24 次审阅触及预算（停在 `budget/context_capacity`）——这是测量值，不是保证。
- 命令的执行目录：`util.with_descriptors` 在单个中断信号下保证命令打开的描述符已经关闭；两个信号分别落在两层收尾的入口时不保证（`docs/design.md`「仍需明确的限制」已写明）。
- 台账 19：既有的 `UnsupportedLedgerTests` 现在把 18 作为被拒的版本之一，覆盖各入口、整棵目录不变。两个入口先验版本的修复加了两个用例（没有锁文件时不新建、整棵目录不变；锁被占用时报版本不支持），撤掉修复后 16 个子用例失败。
- 文档：四项的文档改动各有一份离线核对脚本，把文档里能离线核对的断言逐条对着代码跑，审阅每一轮的反例都收进去；最后一轮的条数分别是审阅容量 216、命令的执行目录 43、连接失败 22（另加读取边界的探针）、观察页 54。脚本不在仓库里。

| 状态文件的读取 | 新模块 `harness/state_files.py` 是读 Harness 自己状态文件的原语：先解析传入的状态根（传入的是指向目录的链接时，读到的是链接目标里的文件），再从解析后的根起逐级以搜索权限、不跟随链接地打开，末级非阻塞打开并以 `fstat` 确认是普通文件；每次调用返回读到、缺失、被拒（链接、管道文件、目录等）、超限、失败五种结果之一，按模块说明不抛 `OSError`。锁（`StateFiles.lock`）也经它，持有锁的对象由先于取得建立的两层收尾（`state_files.holding`）兑现关闭，只保证单个信号（决定 12）；模块里给观察用的持有根（`StateFiles.held`）这一版只有测试调用，观察入口没有用它。按调用点，改经原语的有：台账 `state.json` 的加载（`RunLifecycle.load_run`，`resume`、`abandon` 用）与读写（`RunStore`，含 `store.lock`）、`run.lock`（`run` 在第一次保存台账、尝试发布 `run_created` 之后才取得；`resume`、`abandon` 取得之前先在锁外加载一次台账，取得之后再加载一次；额度等待在持锁期间）、记忆库的初始化锁、私有状态的控制文件 `.harness/.gitignore`、命令目录的探测（`util.validate_command_directories`）与命令进程 journal（见本格末尾）。`run.lock` 是链接、管道文件或目录时以 `evidence/runtime_integrity` 停止；macOS 上并发创建锁文件时没抢到的一方得到的 `ENOENT` 至多重试 3 次；已知目录身份时先在父目录描述符上核对、再创建锁文件，不符为 `runtime_failure/invariant`，不在被换掉的目录里新建锁。仍在原路径上的读点（例子，不是全部）：broker 核对派发是否仍在进行时读台账（`harness/command_server.py` 的 `_source`）、`cleanup-run` 门禁读台账（`cleanup._gate`）与它预览时取 `run.lock` 的 `readonly_lock`、观察器读台账与其他文件（`observe.StateReader` 用它自己的打开与读取，`status RUN` 另有一处按路径读取）、记忆核对来源 run 时读那个 run 的台账（`memory.py` 的 `_source_ledger`）。命令进程 journal（调用目录里的 `process.json`）改为从状态根起经原语逐级读取，一次枚举里每条读一次（这部分没有通过审阅，见 D4-T3）。结构检查（`tests/test_state_files.py` 的 `MIGRATED`）只登记全部读取都已迁移的模块，这一版只有 `run_store.py`，它不是上面这些调用点的清单 |

  - hook 名字读取之后才由别的进程写进配置的 hook 检测不到。
