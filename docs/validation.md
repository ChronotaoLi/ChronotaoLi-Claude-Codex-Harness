本文只记录当前版本（台账 18）已经完成的验证。更早版本的记录在 git 历史里；它们验证的是已经改掉的代码，证明不了现在的行为。

## 验证对象

- 分支 `ledger18-2026-11-13`，台账版本 18，提交 `b0ba960`（运行时、测试与使用文档；本记录在其后的提交里，那些提交不改运行时与测试）；起点 `1361f95`（台账 17）。验证日期 2026-11-16。
- macOS（Darwin 25.6.0），Python 3.15.2。
- 下面的离线结果都来自模拟模型响应（`DemoBackend`、各测试的脚本化后端，以及打印合成信封的本地子进程）加真实 Git、真实验证子进程与真实信号。没有调用任何真实模型，也没有运行真实的 `claude`、`codex`：凡用到 `CLIBackend` 或额度探测的用例，两个可执行文件都换成记录调用的桩。离线结果不证明任何真实模型调用或真实 CLI 接口可用（见[没有运行的](#没有运行的)）。

## 真实 CLI 绊线

第三次运行前把两个绊线脚本 `claude`、`codex` 放在 `PATH` 最前：被调用就把参数追加到日志并以 97 退出。用例里需要 CLI 的地方各自装了记录调用的桩，并在用例结束时断言没有意外调用；绊线兜住桩以外的任何查找。结果：真实 CLI 调用 **0** 次（日志为空）；运行结束后没有遗留的桩进程，临时目录里没有遗留的 `harness-quota-*` 探测目录。

同一份代码上另用一组独立编写的绊线脚本复跑了一次分片套件，结果相同：收集 1,712 = 执行 1,712，通过 1,711、跳过 1，876.8 秒，命中 0 次，没有遗留。

## 没有运行的

**以下各项离线结果证明不了。** 本版本没有运行任何真实账号联调：没有运行 `python3 -m harness smoke`（两种指挥）、`python3 -m harness.tool_smoke`、`python3 -m harness.permission_smoke`，也没有直接运行 `claude` 或 `codex`。

范围边界与修订：

1. 声明了边界之后，指挥是否在边界内规划；范围或需求不清时是否在规划阶段提问；运行中是否用 `add_allowed_paths`／`add_required_commands` 扩展原任务而不拆任务；需要边界外路径时是否直接提交修订（`gpt-6-astra` 与 `claude-fable-5-2` 各一次）。
2. `decide` 的 `TASK_UPDATE` 多出两个字段之后，Codex 严格模式与 Claude `--json-schema` 是否都接受。
3. 范围兜底的往返：首版越界的持有与扩大后发布；修订越界的持有、部分扩大、扩大后落地与拒绝；`--scope` 与 `--operator-decision` 同一次提交。

额度探测：

4. `claude -p /usage` 加 `--strict-mcp-config`、`--max-turns 1` 之后在当时的 Claude Code 版本下是否仍是零调用、`usage_report` 是否照常出现，在 Claude Code 会话内外各一次；`--strict-mcp-config` 是否确实不启动用户的 MCP 服务器，`--setting-sources ""` 之下插件与用户 hooks 是否仍被加载。
5. `codex app-server` 的 `account/rateLimits/read` 是否仍可用；`initialize` 答复里的版本信息与出错时的形状；`rateLimitsByLimitId`、`limitName` 的真实形状；三条消息之间服务端会不会发出需要回应的请求；stdin 关闭后多久退出、会不会派生进程；JSON-RPC 消息不带 `jsonrpc` 字段是否仍被接受；不带 `--ignore-user-config` 时是否读取用户配置里的 MCP、插件或 hooks 并启动进程。
6. Harness 被强杀时遗留的探测进程是否自行退出；Claude 探测的耗时（冷启动、插件）与 5 秒时限是否相称，0.5 秒的 SIGTERM 宽限是否够 CLI 自己收尾。
7. `extra_usage` 启用后各字段的取值类型；Claude 未登录或登录过期时 `/usage` 的结果行，Codex 未登录时的错误码。
