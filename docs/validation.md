## 实测四项发现的修复（2026-11-19）

对象是树 `a721d5d48669300895e8bc30a421945032cf2339`（见[验证对象](#验证对象)），起点是 `f5e7f84`（台账 18）。来由是 2026-11-18 一次外部项目实测记下的五项发现：历史阻断问题超过 60 条后 run 停在 `budget/review_findings`，唯一的出口是 `abandon`；精确命令授权不能指定子项目的执行目录；Claude worker 两次连接重置都以通用调用失败停止、各计一次工作尝试；观察页容易把另一个检出的旧 run 或上次的拒绝读成当前状态；丢弃一个 run 需要多处手工清理。前四项做了修复，下称审阅容量、命令的执行目录、连接失败、观察页；台账版本随之从 18 升到 19。

**第五项（丢弃一个 run）没有交付**：没有任何为它写的代码进入这棵树，`abandon` 与 `cleanup-run` 能做的清理与基线相同（`cleanup-run` 这一轮只改了台账版本的检查顺序，见下表“台账 19”）。**这一轮没有对 Harness 做任何真实账号上的检查**：下面的离线套件、变异、中断注入与探针全部在离线条件下运行，模拟模型响应加真实 Git、真实文件系统、真实子进程与真实信号，被验证的 Harness 运行时与测试套件没有调用真实模型，也没有运行真实的 `claude`、`codex`；审阅过程用了真实模型，见下面的“独立审阅”。没有运行的，以及审阅中记下、这一轮没有修的问题（其中“完成前的窗口”一条需要所有者决定是否修），见[没有运行的](#没有运行的)。

### 变异、中断注入与离线探针

“变异”指在任务的工作树里把关键判定改错、确认有用例失败，再恢复；变异不进版本库。
